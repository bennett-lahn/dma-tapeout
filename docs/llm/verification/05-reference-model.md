# Reference Model and Scoreboard

## Purpose and boundary

The M2 reference package is a pure-Python oracle for V1 descriptor semantics. It owns:

- exact 11-byte TCD serialization and validation,
- deterministic interpretation of one descriptor chain,
- expected PSRAM memory updates,
- expected ordered QPI transactions, and
- mismatch reports that identify the first semantic divergence.

The reference package must not import cocotb, inspect DUT hierarchy, read simulator signals, or reproduce RTL FSM states and counters. It consumes ordinary Python values and independent initial-memory snapshots. Cocotb adapters may pass model inputs and observed monitor records to it.

The oracle models architecture, not timing. QPI phase timing, pin direction, handshake pulse counts, arbitration, and reset convergence belong to `04-timing-in-sim.md` and `06-checkers.md`.

## Pure-Python data contract

### TCD value

Represent one decoded descriptor as an immutable value with these fields:

| Field | Python value | Valid range |
|---|---|---|
| `src_ptr` | `int` | 24-bit field `0x000000..0xFFFFFF`; useful address is `ptr[22:0]` in `0x000000..0x7FFFFF` |
| `dest_ptr` | `int` | same |
| `transfer_len` | `int` | `0..255` |
| `next_tcd` | `int` | same as `src_ptr` |
| `quit` | `bool` | `False` or `True` |
| `src_device` | `int` | `0` or `1` |
| `dest_device` | `int` | `0` or `1` |
| `next_device` | `int` | `0` or `1` |
| `reserved` | `int` | `0..15`, valid V1 stimulus requires `0`. Last field of the software value and last nibble of the 11-byte record (`CTRL_FLAGS[3:0]`); also the packed LSB of RTL `tcd_t` (D31). The DUT latches it; V1 control ignores it. |

Python `bool` is a subclass of `int`, so range validation must explicitly reject booleans for integer fields. Encoding must reject negative values, values outside the 24-bit field (`0..0xFFFFFF`), non-integers, and nonzero reserved bits. Pointer bit 23 is allowed (don't-care; D35). It must not mask invalid input into range.

Decoding separates representation from V1 validity:

1. `decode_tcd(raw)` requires exactly 11 bytes and preserves all encoded bits, including `reserved`.
2. `validate_tcd(tcd)` applies the V1 ranges above and rejects nonzero `reserved`.
3. Chain interpretation validates each descriptor after decoding and stops with a reference-model error before generating data transactions for an invalid descriptor.

This split allows a negative test to decode and diagnose a malformed descriptor without silently treating it as legal stimulus.

### Exact 11-byte serialization

All three pointer fields are unsigned 24-bit values serialized most-significant byte first. Payload data is not byte-swapped.

| Offset | Encoded byte |
|---|---|
| 0 | `(src_ptr >> 16) & 0xFF` |
| 1 | `(src_ptr >> 8) & 0xFF` |
| 2 | `src_ptr & 0xFF` |
| 3 | `(dest_ptr >> 16) & 0xFF` |
| 4 | `(dest_ptr >> 8) & 0xFF` |
| 5 | `dest_ptr & 0xFF` |
| 6 | `transfer_len` |
| 7 | `(next_tcd >> 16) & 0xFF` |
| 8 | `(next_tcd >> 8) & 0xFF` |
| 9 | `next_tcd & 0xFF` |
| 10 | `(next_device << 7) | (dest_device << 6) | (src_device << 5) | (quit << 4) | reserved` |

`encode_tcd(tcd)` returns a `bytes` object of length 11. `decode_tcd(encode_tcd(tcd)) == tcd` is required for every valid V1 TCD.

A mandatory unit vector is:

```text
src_ptr       = 0x123456
dest_ptr      = 0x234567
transfer_len  = 0x89
next_tcd      = 0x345678
quit          = 0
src_device    = 1
dest_device   = 0
next_device   = 1
reserved      = 0
bytes         = 12 34 56 23 45 67 89 34 56 78 A0
```

### Memory representation

The interpreter receives two independent byte-addressed memory images keyed by device `0` and `1`. A dense `bytearray` or sparse mapping may implement an image, but the public operations are:

- `read(device, address, length) -> bytes`
- `write(device, address, data) -> None`
- `clone() -> independent image`

Every access uses widened Python arithmetic and must fit wholly in `0x000000..0x7FFFFF`. In particular:

- an 11-byte fetch requires `fetch_addr + 10 <= 0x7FFFFF`,
- a data access of length `k > 0` requires `addr + k - 1 <= 0x7FFFFF`, and
- zero-length reads and writes are never generated by the chain interpreter.

Uninitialized-byte behavior is a test configuration decision, not an implicit zero. The initializer must either define every readable byte or configure one explicit fill byte and record it in the run manifest.

## Golden chain interpreter

### Inputs

One interpretation run receives:

- an independent clone of the initial memory for devices 0 and 1,
- `dma_buf_depth`, an integer at least 1,
- a descriptor-fetch budget,
- a transaction budget, and
- the V1 fixed head, which is always device 0, address `0x000000`.

The budgets make cyclic or self-pointing chains terminate deterministically in Python. Exhausting a budget is reported as `reference_limit`, with the next device/address and recent chain path. It is not interpreted as `QUIT`, `DONE`, or a DUT pass.

### Algorithm

The normative interpreter is:

```text
memory = clone(initial_memory)
fetch_device = 0
fetch_addr = 0x000000

loop:
    raw = memory.read(fetch_device, fetch_addr, 11)
    emit FETCH_READ(device=fetch_device, address=fetch_addr,
                    length=11, data=raw)
    tcd = validate_tcd(decode_tcd(raw))

    if tcd.quit:
        stop with normal completion

    src_addr = tcd.src_ptr
    dest_addr = tcd.dest_ptr
    remaining = tcd.transfer_len

    while remaining > 0:
        k = min(dma_buf_depth, remaining)
        payload = memory.read(tcd.src_device, src_addr, k)
        emit DATA_READ(device=tcd.src_device, address=src_addr,
                       length=k, data=payload)
        emit DATA_WRITE(device=tcd.dest_device, address=dest_addr,
                        length=k, data=payload)
        memory.write(tcd.dest_device, dest_addr, payload)
        remaining -= k
        if remaining > 0:
            src_addr += k
            dest_addr += k

    fetch_device = tcd.next_device
    fetch_addr = tcd.next_tcd
```

The following rules are deliberate:

- `QUIT=1` takes priority over `TRANSFER_LEN`. The quit descriptor is fetched and logged, but its source, destination, length, and next fields are not executed.
- `TRANSFER_LEN=0` emits no data read or write and immediately follows `NEXT_TCD` on `NEXT_DEVICE`.
- Address `0x000000` is a valid source, destination, or next link. It is not a null pointer.
- Device selection comes only from `CTRL_FLAGS`, never from pointer bit 23 (`ptr[23]` is don't-care; D35).
- Same-device and cross-device copies use the same algorithm.
- Reads observe the current model memory at the time of each chunk. A chunk reads all `k` bytes before its write mutates memory. This reproduces the DMA's ordered read-then-write behavior for overlapping regions and does not impose whole-transfer `memmove` semantics.
- Pointer increments occur only when bytes remain. Final working-register pointer values are intentionally outside the oracle because architecture declares them unconsumed.
- A later TCD fetch reads current memory. A preceding copy may therefore modify a descriptor that has not yet been fetched.
- A normal run completes only by fetching a quit descriptor. Budget exhaustion and invalid memory/TCD input are model errors, not normal completion.

For the V1 tapeout configuration `dma_buf_depth=5`. The reference model accepts any positive depth up to `DMA_BUF_DEPTH_MAX` for the M5 `1..8` sweep; RTL selects depth via module parameter `DMA_BUF_DEPTH`.

## Normalized transaction log

### Record schema

The pin-level QPI monitor and the reference interpreter exchange immutable normalized records with these equality fields:

| Field | Meaning |
|---|---|
| `index` | Zero-based order within one DMA scoreboard epoch |
| `kind` | `FETCH_READ`, `DATA_READ`, or `DATA_WRITE` |
| `opcode` | Integer `0xEB` for reads or `0x02` for writes |
| `device` | `0` for RAM A or `1` for RAM B |
| `address` | Effective QPI address `A[22:0]` (wire bit 23 don't-care / masked; D35) |
| `length` | Payload byte count for this CE# assertion |
| `data` | Payload bytes in wire order |

Diagnostic metadata may add `start_time`, `end_time`, test name, simulator, or raw nibble trace. Metadata is excluded from semantic equality.

One external CE# assertion is one transaction record. Transaction order is strict:

1. one 11-byte `FETCH_READ`,
2. zero or more alternating `DATA_READ`, `DATA_WRITE` pairs for that TCD,
3. the next `FETCH_READ`, and
4. a final `FETCH_READ` for the quit descriptor.

The monitor assigns `kind` without looking at DUT hierarchy. Every `0x02` is `DATA_WRITE`. A read is `FETCH_READ` only when it matches the next expected fetch position in ordered comparison; otherwise it is `DATA_READ`. For raw observed-log storage, the neutral values `READ` and `WRITE` may be retained and classified during comparison. Opcode, device, address, length, and data must never be inferred from the expected record.

Host pass-through traffic is excluded. An L1 scoreboard epoch opens on the top-observable high-to-low transition of `DONE` caused by an accepted START after `BUS_GNT` is low. The host driver records the corresponding raw START stimulus, but the reference package does not inspect synchronizer hierarchy. The epoch closes on normal quit completion, test-directed reset, or a fatal checker/model error.

### Observed transaction completion

A normal observed record is appended only after CE# returns high and the monitor has decoded a complete command, address, wait phase, and payload. A malformed or reset-aborted CE# interval is retained as a separate diagnostic event and is not rewritten into a normal record.

For a normally completed run, expected and observed logs must have identical length and identical equality fields at every index. An extra, missing, reordered, truncated, or duplicated transaction is a failure even when final destination bytes happen to match.

## Dual-axis scoreboard

### Axis 1 - Ordered transaction comparison

Compare records in order and stop semantic comparison at the first mismatch while retaining context. Do not sort by address or collapse adjacent transactions. Chunk boundaries are architecturally visible because `DMA_BUF_DEPTH` determines QPI transaction length.

The ordered log catches errors that a final memory image can hide, including:

- wrong descriptor device or address,
- duplicated or skipped reads and writes,
- wrong source data followed by a compensating write,
- an illegal data transaction for a quit or zero-length TCD,
- wrong chunk length,
- wrong next-device selection, and
- accidental access to the correct bytes in the wrong order.

### Axis 2 - Final memory comparison

On normal quit completion, compare both final PSRAM images against the interpreter result. At minimum compare every address that was initialized, read, written, or designated as a guard region. Sparse implementations compare the union of defined and touched addresses plus explicit guards.

Report:

- bytes expected to change but unchanged,
- changed bytes with the wrong value, and
- unexpected writes outside the expected write set.

Read-only source regions, descriptors, neighboring sentinels, and the inactive device are part of the guard set unless a test intentionally aliases them.

Both axes are required. A test does not pass because only the destination range matches.

### Reset-interrupted epochs

`rst_n` is active low and resets sequential RTL only on a rising `clk` edge. The scoreboard must not terminate or demand reset state merely because `rst_n` changed low between clock edges.

For a reset test:

1. Continue monitoring until the first rising `clk` edge sampled with `rst_n=0`.
2. Compare every normal transaction completed before that edge against the same-length expected prefix.
3. Preserve any transaction active at that edge as an aborted diagnostic event.
4. Do not require the full chain log or full-chain final image.
5. Derive the expected committed memory from the expected completed prefix. Addresses that the PSRAM model may have committed during an aborted write are reported separately and are compared only if the PSRAM model defines byte-commit behavior for that exact abort point.
6. After the reset edge, require no new ASIC transaction until reset is released and a new START is accepted. Reset convergence and OE release are checked by `06-checkers.md`.

Tests that require an exact post-reset memory image should schedule reset between transactions or use a PSRAM model with explicitly specified partial-write commit behavior.

### Repeated-run epochs after reset

`TC-RESET-REPEAT` in `08-stimulus-and-coverage.md` runs an identical chain twice across a reset boundary and requires the second run to behave exactly like the first. The scoreboard supports this as two independent epochs, not one extended epoch:

1. run the golden interpreter and open a normal scoreboard epoch for the first pass, using its own initial memory clone,
2. after the reset boundary, re-initialize memory identically and run the golden interpreter and a second independent scoreboard epoch for the second pass,
3. require each epoch to independently pass both scoreboard axes against the golden interpreter, and
4. additionally require the two epochs' observed transaction logs to be equal to each other field-for-field, in order.

Step 4 is a stronger equality check than either epoch's oracle comparison alone. It specifically targets working state, counters, or pointers that could otherwise leak across the reset boundary and produce a result that still matches the golden interpreter by coincidence while differing from the first run.

## Mismatch diagnostics

Every scoreboard failure prints the first failing axis and a stable, copy-paste-friendly report. The minimum header is:

```text
SCOREBOARD FAIL axis=<transactions|memory|reference>
level=<L1|L2> sim=<name/version> seed=<n> depth=<n> timing=<profile>
epoch=<n> expected_transactions=<n> observed_transactions=<n>
```

### Transaction mismatch

Include:

- first mismatching index,
- expected and observed record in canonical single-line form,
- field-by-field differences,
- up to three records before and after the mismatch,
- active TCD fetch device/address and descriptor bytes,
- decoded TCD fields,
- remaining length and chunk number,
- observed raw nibbles and timestamps when available, and
- the reproduction command.

Canonical record example:

```text
#004 DATA_WRITE op=02 dev=1 addr=0x234568 len=1 data=A5
```

If one side has no record, print `<missing>` rather than fabricating zero values.

### Memory mismatch

Group contiguous addresses, but identify the first differing byte precisely:

```text
dev=1 addr=0x234568 expected=A5 observed=5A
region=destination tcd_fetch=0:0x000000 chunk=1
```

Also show a bounded hexadecimal window around the byte and classify it as `missing_write`, `wrong_data`, or `unexpected_write`. Do not dump an entire 8 MB image into the main log. Store full machine-readable expected/observed transaction traces and diff ranges in the run directory.

### Reference-model error

Use a distinct `reference` axis for invalid TCD encoding, out-of-range access, undefined memory, or budget exhaustion. Include the chain path as `(device,address)` pairs and never report such an error as a DUT mismatch.

## Independence and review rules

- Keep TCD constants in the reference package as architecture constants with comments pointing to `../04-tcd-and-datapath.md`. Do not import or parse SystemVerilog.
- Unit-test encode/decode, fixed head, quit priority, zero length, both cross-device directions, overlapping ranges, descriptor overwrite before fetch, bounds, and budget exhaustion before connecting the model to cocotb.
- Use independently written pin decoding for observed transactions. The expected model must not consume the PSRAM model's internal access log as its observed axis.
- The PSRAM model's final storage may supply observed memory, but the reference interpreter always starts from a separate clone.
- Unknown or high-impedance observed values are failures with raw logic text. They are never coerced to zero.

## M2 acceptance

- The mandatory TCD vector encodes and round-trips exactly.
- Pure-Python unit cases cover all interpreter rules above.
- One same-device, one cross-device in each direction, one chained, one zero-length, one quit-only, and one overlapping case pass both scoreboard axes.
- Transaction mismatches identify the first divergent field and retain surrounding trace context.
- Memory mismatches identify device, byte address, expected value, observed value, and classification.
- Reset tests apply prefix semantics and synchronous-reset sampling explicitly.
- `TC-RESET-REPEAT` produces two independently oracle-passing epochs whose observed transaction logs are field-for-field identical to each other.

**Status:** `pass` (2026-08-08). Pure-Python reference pytest and L1 directed dual-axis scoreboard evidence are recorded under `01-strategy.md` (M2 acceptance status). Generator placement refuses destination writes into descriptor slots (no-clobber); intentional descriptor-overwrite-before-fetch remains oracle-legal but is not default stimulus.
